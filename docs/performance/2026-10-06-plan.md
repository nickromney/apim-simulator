# Synthetic cache profiling plan — 6 October 2026

No optimizer or production behavior change. The source comparison is the three
existing LRU wrappers retained versus bypassed, preserving request-local reuse.
Both modes run identical in-memory HTTPX ASGI/MockTransport inputs, checked
against committed policy/routing golden bytes before and after collection.

The seeded schedule uses balanced randomized blocks: three discarded process
warmup blocks, then ten measurement blocks. Each block runs the four distinct
scenario/mode conditions once. Versioned routes vary the resource ID in every
warmup/measured request; expressions use the existing policy workload. Each
process retains 20 internal request warmups then 1,000 measured requests, with
100 route definitions for the versioned scenario. Child-process wall/CPU and
whole-process RSS are distinct from request-loop percentiles.

The predeclared host gate requires five numeric interval CPU observations with
at least 85% idle and at most 10 percentage points of spread, after other agents'
heavy gates finish. Failed attempts preserve fingerprint and preflight records,
and never launch a benchmark workload. The gate is not relaxed to fit observations.
Each timed process retains numeric CPU/load samples immediately before/after it;
load averages can retain earlier build activity, and these boundary samples do
not establish uninterrupted isolation between observations. No other process
names, user data, OS/power settings, or affinity changes are collected/applied.

Separate cProfile and tracemalloc processes use the same inputs and are excluded
from latency tables. cProfile covers the measured request loop after internal
warmups; application cumulative parents overlap and coroutine resumes affect
call counts. Tracemalloc starts after imports, before app construction, and
stops after request/context cleanup: peak traced Python allocation is not RSS
or retained cache size; application retained line snapshots are end-of-workload
survivors, not total allocation traffic. No I/O/off-CPU/contention claim.

Commands (from this checkout's frozen offline dev environment):

```sh
uv run --frozen --offline --extra dev python scripts/collect_cache_profiles.py --output NEW_DIRECTORY
uv run --frozen --offline --extra dev python scripts/profile_cache_modes.py --output NEW_PROFILE_DIRECTORY
```

The collectors require macOS `top`, `sysctl`, `pmset` and numeric CPU access.
`--allow-shared-host` exists for explicitly qualified observations in future
runs, not for a causal comparison or a regression threshold. Never reuse an
output directory or discard unfavorable measured rows. Source/toolchain/power/
filesystem fingerprints and raw process rows belong beside the final report.

The collector also checks each before/after workload observation against the preflight idle envelope. A failed before observation prevents the next workload; a failed after observation retains the row and rejects the collection without writing a successful summary. Boundary samples cannot prove uninterrupted isolation. Historical fingerprints and hash receipts describe their captured collector/source versions; they do not attest to the final edited collector.
